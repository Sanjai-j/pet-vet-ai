# Deploying Pet Vet AI on Render + Neon (single service)

> **This page describes the one-service layout, which now needs a paid Render
> instance.** The Angular production build peaks at roughly 760 MB and a Render
> Free instance has 512 MB, so `npm run build` is killed there. The zero-cost
> layout — Angular on Cloudflare Pages, a Pages Function proxying `/api/*` and
> the socket, and this API alone on Render Free — is in
> [DEPLOY_FREE.md](DEPLOY_FREE.md), and `render.yaml` in the repository root now
> describes that API-only service. Use this page only if you are deploying the
> API and the app together on a **Starter** (2 GB) instance.

In this layout **one Render web service** runs the Express API, the WebSocket
server and serves the built Angular app, and **Neon** hosts PostgreSQL.

```
Browser ──HTTPS──▶ Render web service (Node 22)
                    ├── /api/*     Express API (files are streamed from /api/files/:id)
                    ├── /ws        chat + consultation signalling
                    └── /*         Angular single-page app
                          │
                          └──TLS──▶ Neon PostgreSQL (pooled connection)
```

Everything the app needs to stay durable lives in Postgres: users, pets,
records, appointments, chat, the knowledge base — and, on Render, uploaded
files too, because the free instance has no persistent disk.

---

## 0. What you need first

| Thing | Why |
| --- | --- |
| A GitHub repository containing this project | Render deploys from Git, not from a folder upload |
| A [Render](https://render.com) account | Hosts the web service |
| A [Neon](https://neon.tech) account | Hosts PostgreSQL (free, never expires) |
| Node 20 or 22 locally | Only to run the pre-deploy checks |

> **Do not use Render's own free PostgreSQL** for this project: Render deletes
> free databases 30 days after creation, which would wipe a live site.

## 1. Push the project to GitHub

```bash
git init
git add .
git commit -m "Pet Vet AI"
git branch -M main
git remote add origin https://github.com/<you>/pet-vet-ai.git
git push -u origin main
```

`.gitignore` already excludes `.env`, `.data/`, `uploads/`, `node_modules/`
and both `dist/` directories, so no secrets or build output are committed.

---

## 2. Create the database on Neon

1. Neon dashboard → **New Project**. Pick the region closest to your Render
   region (Singapore pairs with Render's Singapore region), PostgreSQL 16.
2. On the project's **Connect** panel, choose the **pooled** connection string
   (the host contains `-pooler`). It looks like:

   ```
   postgresql://USER:PASSWORD@ep-xxx-pooler.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
   ```

3. Copy it. That whole string is `DATABASE_URL`.

The pooled endpoint matters: Render's free instance opens a small, fixed
number of connections, and pooling keeps you under Neon's connection limit.
The API already caps its pool at 10 connections (`apps/api/src/db.ts`).

The schema is created automatically on first boot (migrations `001_init` to
`005_file_storage`). The seed loads **reference catalogs only** — species,
brands, food-safety entries, approved vaccine schedules, knowledge base,
nutrition guidance. It never creates people, pets, clinics or records, so the
deploy starts empty and redeploys never overwrite real data.

## 3. Create the service on Render

### Option A — Blueprint

The Blueprint in `render.yaml` now creates the **API-only** service used by the
free Cloudflare Pages layout; it does not build or serve Angular. For this
single-service layout, create the service manually with the settings in
Option B and set the plan to **Starter**.

`JWT_SECRET` is generated by Render. `WEB_ORIGIN` must be the service's own
public URL (`https://<service>.onrender.com`) so CORS and the WebSocket origin
check accept the app it serves.

### Option B — Manual web service

Create a **Web Service** from your repository with these settings:

| Setting | Value |
| --- | --- |
| Runtime | Node |
| Region | Singapore (or the one nearest your Neon region) |
| Build command | `NODE_ENV=development npm run install:all && npm run build` |
| Start command | `npm run start:prod` |
| Health check path | `/api/health` |
| Instance type | **Starter** (the Angular build does not fit in 512 MB) |

Then add these environment variables:

| Variable | Value | Notes |
| --- | --- | --- |
| `NODE_VERSION` | `22` | |
| `NODE_ENV` | `production` | enables TLS for Postgres and strict config checks |
| `DATABASE_URL` | Neon pooled URL | secret |
| `JWT_SECRET` | long random string | `openssl rand -hex 48` or `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"` |
| `WEB_ORIGIN` | `https://<your-service>.onrender.com` | must match the public URL exactly |
| `SEED_CATALOG` | `true` | seeds reference catalogs into an empty database |
| `OVERPASS_ENABLED` | `true` | free, keyless OpenStreetMap nearby-hospital search |
| `NOMINATIM_USER_AGENT` | `PetVetAI/1.0 (you@example.com)` | OSM asks for a contact address in the User-Agent |
| `FILE_STORAGE` | `db` | uploads survive restarts |
| `APP_TIMEZONE` | `Asia/Kolkata` | drives "today", reminders and labels |

`PORT` is injected by Render. The server binds to it automatically.

## 4. Verify the deployment

Run these in order; each one exercises a real path in the code.

```bash
BASE=https://<your-service>.onrender.com

curl -s $BASE/api/health                       # {"status":"ok","database":"ok",...}
curl -s -o /dev/null -w '%{http_code}\n' $BASE/            # 200 — the SPA shell
curl -s $BASE/api/config/public                # feature flags for this deployment
```

Then in a browser, using an account you created:

1. **Register** an owner account and **sign in** as the administrator created
   by `npm run create-admin`.
2. **Dashboard** shows pets, upcoming care and records.
3. **Pet detail** → upload a photo. This is the path that breaks on hosts
   without a disk; after a **Manual Deploy → Restart**, the photo must still
   load, which proves it is in Postgres.
4. **Find care** → share your location (or type a city). Nearby vet hospitals
   must come back in distance order from OpenStreetMap with an "Open in Maps"
   link.
5. **Messages** → send a message in two browser windows. The WebSocket must
   stay connected across `wss://`.
6. **Pet Vet AI** → ask a question and confirm the answer streams back.
7. **Admin** → the knowledge base and vaccine schedules load (reference
   catalogs; the review queues start empty because the seed ships no records).

Everything except the optional third-party features below works on a
key-less free deployment, using the deterministic AI composer and the built-in
OpenStreetMap lookup.

## 5. Free-tier realities (and how this project handles them)

| Reality | Effect | Mitigation |
| --- | --- | --- |
| Free instances **spin down after ~15 min of inactivity** | First request after idle takes 30–60 s | Keep it warm with a free uptime pinger, or accept the cold start |
| Free instances have **no persistent disk** | Uploaded files vanish on redeploy | `FILE_STORAGE=db` stores files as `bytea` in Postgres |
| Free instances have **512 MB RAM**, shared with the build | The Angular production build peaked at roughly 760 MB in local measurement, so a free-tier build can be killed for exceeding memory | Use a Starter instance (2 GB) for the build, or host the built Angular app on a static site and keep only the API on Render |
| Render **free PostgreSQL expires after 30 days** | Data loss | Use Neon instead (this guide) |
| **750 free instance hours/month** per workspace | One always-on service fits | Run one service, not two |
| Neon free has **0.5 GB storage** and suspends when idle | First query after idle is slow | Automatic; the pool reconnects on demand |
| In-process **reminder scheduler stops when the instance sleeps** | Reminder digests are skipped while asleep | They run on the next wake-up; add Render Cron + an endpoint if you need exact timing |
| **WebSockets are supported** on Render free | Chat and consultations work | Socket origin is checked against `WEB_ORIGIN` |

Limits change; check [Render pricing](https://render.com/pricing) and
[Neon pricing](https://neon.tech/pricing) before relying on a number.

## 6. Before you share the link

The deployment ships with reference catalogs only — no people, pets, clinics
or records. Do this once after the first deploy:

1. **Create the administrator.** Run this with the same `DATABASE_URL` in the
   environment (for example from Render's shell tab, or locally with
   `DATABASE_URL=...` exported):

   ```bash
   npm run create-admin --prefix apps/api -- you@example.com "A-strong-password" "Your Name"
   ```

   That account is the only one that can approve credentials and review
   knowledge. It is not advertised anywhere and no password is returned by any
   endpoint.

2. **Register the accounts you need.** Owners and veterinarians sign up on
   `/register`. Veterinarians stay hidden from the directory until the
   administrator approves their credentials.
3. **Hospital listings come from OpenStreetMap by default** — community-mapped,
   incomplete, and never a Pet Vet AI verification. Point `GOOGLE_MAPS_API_KEY`
   at Google Places if you want better coverage, and put a real contact address
   in `NOMINATIM_USER_AGENT` as OSM asks.
4. Treat the AI output as first-aid guidance. It already refuses to diagnose
   or prescribe, shows its sources, and escalates emergencies.

## 7. Optional paid/free external services

Each one is optional; the UI degrades with a clear explanation instead of
failing.

| Feature | Variables | Notes |
| --- | --- | --- |
| Hospital listings | `OVERPASS_ENABLED` (free default), `GOOGLE_MAPS_API_KEY` (upgrade) | OpenStreetMap needs no key; Google Places adds ratings and better coverage |
| Generative answers | `LLM_PROVIDER=openai-compatible`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | Without a key the deterministic, source-cited composer is used |
| Live web search | `EXA_API_KEY` | Server-side only |
| Email reminders | `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `EMAIL_FROM` | Any SMTP provider |
| Browser push | `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | `npx web-push generate-vapid-keys` |
| Live clinic maps | `GOOGLE_MAPS_API_KEY`, `GOOGLE_MAPS_BROWSER_KEY`, `GOOGLE_MAPS_MAP_ID` | Restrict keys in Google Cloud |
| Video consultations | `TURN_URL`, `TURN_USERNAME`, `TURN_CREDENTIAL` | STUN-only works on many networks; TURN needs a hosted server (not free) |

Add these in Render → your service → **Environment** and redeploy. Secrets
never reach the browser except `GOOGLE_MAPS_BROWSER_KEY`, which is designed to
be public and must be referrer-restricted.

## 8. Updating the site

```bash
git add .
git commit -m "Describe the change"
git push
```

Render redeploys on push to the connected branch (`autoDeploy: true`).
Migrations run at boot, so additive schema changes apply themselves. If a
deploy ever fails, Render keeps the previous live version serving traffic.

## 9. Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `JWT_SECRET must be set to a strong secret in production` | Missing or default secret | Set `JWT_SECRET` (Render's `generateValue` does this) |
| `no pg_hba.conf entry ... no encryption` / `SSL required` | TLS mismatch | Neon needs TLS: leave `DATABASE_SSL` unset (or `true`). Set `false` only for a local server without TLS |
| `too many connections` | Using Neon's direct endpoint, or several replicas | Use the `-pooler` host and keep one instance |
| `password authentication failed` | Password rotated in Neon | Re-copy `DATABASE_URL` |
| Blank page, unstyled HTML | A stale build | Redeploy; the build regenerates both `dist/` directories |
| CORS error in the browser console | `WEB_ORIGIN` ≠ the real public URL | Set it to the exact origin, no trailing slash |
| `Upload failed` / 404 on an uploaded image | `FILE_STORAGE=disk` on a host without a disk | Set `FILE_STORAGE=db` and redeploy |
| WebSocket closes immediately | Origin mismatch | Same `WEB_ORIGIN` fix; the socket checks it |
| AI answers say "live model not configured" | No LLM key | Expected; set `LLM_*` or use the built-in composer |
| Build fails on `tsc` | Type error in a change | Run `npm run typecheck` locally first |
| `sh: 1: ng: not found` during the build | `NODE_ENV=production` is set while installing, so npm drops devDependencies — and the Angular CLI is one of them | Prefix the install/build with `NODE_ENV=development`, as `render.yaml` does |
| `tsx: not found` at startup | Started with `npm run start:api`, which runs `tsx src/server.ts` — `tsx` is a devDependency and is not installed in production | Use `npm run start:prod` (`node apps/api/dist/server.js`) and make sure the build ran `npm run build:api` (plain `npm run build` does) |

Logs: Render → your service → **Logs**. Startup prints the database mode, the
AI mode and the listening port.

## 10. Local production rehearsal

Run the exact production path before deploying:

```bash
NODE_ENV=production JWT_SECRET="$(openssl rand -hex 48)" \
DATABASE_URL="postgresql://…neon…" WEB_ORIGIN=http://localhost:4101 \
FILE_STORAGE=db PORT=4101 npm run build

NODE_ENV=production JWT_SECRET="$(openssl rand -hex 48)" \
DATABASE_URL="postgresql://…neon…" WEB_ORIGIN=http://localhost:4101 \
FILE_STORAGE=db PORT=4101 npm run start:prod
```

Open <http://localhost:4101> — this is the same single-process setup Render
runs.
